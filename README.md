# Folly Beach surf-window forecast

A static page that scores the next 7 days of surf at Folly Beach, SC and shows only the windows worth your time, color-coded by quality.

- **Bright green** — stellar (4ft @ 11s, SE swell, light NW wind, mid-rise to high tide territory)
- **Light green** — good
- **Yellow** — decent
- **Orange** — marginal but worth knowing about
- Anything below orange is hidden

## Data sources

- **Open-Meteo Marine API** — hourly swell height, direction, period (ECMWF Wave + GFS Wave models)
- **Open-Meteo Forecast API** — hourly 10m wind speed, direction, gusts
- **NOAA CO-OPS** — tide hi/lo predictions for Charleston (station 8665530)
- **NDBC buoy 41004** — current observations panel (Edisto, ~40nm offshore)

All free, no API keys.

## Scoring

For each daylight hour:

```
score = wave · swell_dir · wind_dir · wind_speed · tide
```

Each factor is 0–1 and they multiply. A zero in any factor (e.g. low tide, crossshore wind, sub-surfable energy) zeroes the hour out. See `config.py` for tunable thresholds and `score.py` for the per-factor curves.

Consecutive hours that all clear the orange threshold get grouped into windows of ≥ 2 hours. Each window's color = bucket of its peak hour.

## Local use

```bash
python3 main.py            # writes docs/index.html
open docs/index.html       # view in browser
```

To preview the four color buckets with synthetic data:

```bash
python3 test_render.py     # writes docs/test.html (gitignored)
open docs/test.html
```

## Deploying to GitHub Pages

One-time setup, ~5 minutes of clicking.

1. **Create a new GitHub repo.** Go to https://github.com/new — call it `folly-surf-forecast` (or anything). Public is fine. Don't add a README or .gitignore — they're already in this directory.

2. **Push this directory.** From `folly-surf-forecast/`:

   ```bash
   git init
   git add .
   git commit -m "initial"
   git branch -M main
   git remote add origin git@github.com:<your-username>/folly-surf-forecast.git
   git push -u origin main
   ```

   (Use the HTTPS URL if you don't have SSH keys configured: `https://github.com/<your-username>/folly-surf-forecast.git`.)

3. **Enable GitHub Pages.** In the repo on github.com:

   - Go to **Settings** → **Pages**
   - Source: **Deploy from a branch**
   - Branch: **main**, folder: **/docs**
   - Save

   You'll get a URL like `https://<your-username>.github.io/folly-surf-forecast/` within a minute or two.

4. **Trigger the first build.** Go to **Actions**, find "Update forecast", click **Run workflow**. After ~30 seconds the workflow will fetch the latest data and commit `docs/index.html`. Pages will publish it.

5. **Bookmark the URL** on your phone home screen and desktop. The page auto-refreshes every 15 minutes (HTML meta refresh) and the data is regenerated every 3 hours by the GitHub Actions cron.

## Tuning

If a window scores higher or lower than your gut says it should, edit thresholds in `config.py`:

- `BRIGHT_GREEN`, `LIGHT_GREEN`, `YELLOW`, `ORANGE` — color bucket cutoffs
- `WAVE_ENERGY_FLOOR` / `_CEIL` — what counts as too small or as stellar
- `WAVE_CURVE_EXPONENT` — shape of the wave-energy ramp (lower = generous, higher = strict)
- `WIND_SPEED_RAMP` — knot thresholds for wind-speed penalties
- `SWELL_DIR_LO` / `_HI` / `_BEST` — acceptable swell direction arc
- `SHORE_NORMAL_DEG` — only change if you start surfing somewhere with a different orientation

After changing config, run `python3 main.py` locally to see the effect, or push and let the workflow regenerate.

## Files

- `config.py` — all the knobs
- `fetch.py` — pulls the three APIs
- `score.py` — per-factor scoring + window grouping
- `render.py` — HTML template
- `main.py` — orchestrates fetch → score → render
- `test_render.py` — synthetic data for visual smoke-testing the renderer
- `.github/workflows/update.yml` — runs the pipeline every 3 hours
- `docs/index.html` — the published page (regenerated by the pipeline)
